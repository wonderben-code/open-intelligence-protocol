# Conformance

| File                       | What it is                                                                                                                                   |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| [coverage.md](coverage.md) | Every clause of the specifications, whether a passing test cites it, and the state of the golden vectors. Generated by `pnpm spec:coverage`. |
| [plan.json](plan.json)     | Which milestone of [BUILD.md](../../BUILD.md) owes each clause and each kind of vector case, and which milestones are completed.             |

## How the gate works

1. `scripts/spec-clauses.ts` extracts every numbered clause of `spec/*.md` into [`spec/clauses.json`](../../spec/clauses.json), with the BCP 14 key words each contains. A clause is **MUST-level** if it contains MUST, MUST NOT, REQUIRED, SHALL or SHALL NOT.
2. A test cites the clauses it enforces by putting `clause("L1 6.4")` in its name ([`@oip/testkit`](../../packages/testkit)).
3. `pnpm spec:coverage` runs the tests, counts the passing tests that cite each clause, and writes [coverage.md](coverage.md).
4. It fails if:
   - a MUST-level clause owed by a completed milestone has no passing test;
   - a kind of vector case, or a positive check, owed by a completed milestone does not pass;
   - a MUST-level clause is planned for a milestone after M12;
   - a test cites something that is not a clause.

Completing a milestone means adding it to `completed` in [plan.json](plan.json). From then on its clauses and its vector cases must stay covered.

A citation says that a test enforces part of a clause. It does not say the clause is fully tested: one clause often holds several requirements. The milestone reviews check that.

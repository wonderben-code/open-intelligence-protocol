# Threat model: the host

For `@oip/host` as built in M5: [README](../../packages/host/README.md), Layer 1, Sections 10, 12 and 13. Its archive of identity logs is the `LogArchive` of `@oip/server`, whose threats are in [the resolver's model](resolver.md). What is the host's own is what it does with a record (`host.ts`), its HTTP interface (`app.ts`), its sockets (`sockets.ts`, `upgrade.ts`), its asking of resolvers (`lookup.ts`) and its process (`main.ts`).

## Assets

1. **A mind's mail.** The packets and sealed records kept for a mind until it takes them. Mail that is lost, or given to another, is the worst a host can do.
2. **What the host serves as the mind's**: its bundle, its feed, the records the feed lists. A reader takes these as the mind's own words, and verifies them.
3. **The mind's reachability.** A host that is down, or full, makes the mind unreachable at this endpoint.
4. **First-seen times** of the proofs on packets it accepted and entries it took, in the archive.
5. **A mind's operational key**, only in a program that builds on `Host` and gives it a `signer`. The command `oip-host` holds no key and no secret.

Sealed records are opaque to the host. It cannot read them, and it is not trusted to.

## Who can reach it

| Entry point                                         | Caller                                                         | Trusted with                                                                      |
| --------------------------------------------------- | -------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| `GET /.well-known/oip/mind/…`                       | Anyone                                                         | Nothing                                                                           |
| `POST …/inbox`, `POST …/mailbox`                    | Anyone                                                         | Nothing: a packet at an inbox is verified; a mailbox bounds what it keeps         |
| `GET …/mailbox`, `DELETE …/mailbox/<cursor>`        | The mind, by a signed request                                  | Its own mail                                                                      |
| `PUT /oip/v1/minds/m`, `PUT …/obj/…`, `POST …/feed` | The mind, by a signed request, if the operator admits it       | What is served as its own, within its quotas                                      |
| `GET …/ws`                                          | Anyone for the handshake; any mind that authenticates after it | A sender: what the inbox trusts it with. The mind itself: its own mail            |
| A resolver in `RESOLVERS`                           | The operator's choice                                          | Nothing: what it answers is verified. It learns which senders the host asks about |
| `/healthz`, `/readyz`, `/metrics`                   | Anyone who can reach the port                                  | Nothing. Put `/metrics` behind the operator's network                             |
| The environment, the database file                  | The operator                                                   | Everything                                                                        |
| A proxy in front, where `TRUSTED_PROXIES` is not 0  | The operator's proxy                                           | The client's address, and TLS                                                     |

## Threats

### Spoofing

| Threat                                                                             | What stops it                                                                                                                                                                                | Left                                                                                                                           |
| ---------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| A packet claims a sender that did not sign it                                      | `receivePacket` of `@oip/net` judges it by the sender's log before it is kept (`host.ts` `deliver`; `host.test.ts`: "is refused for what a recipient may not accept")                        | A mailbox does not judge: it is where a mind's mail goes when nothing else takes it, and the mind judges what it drains (13.5) |
| A stranger drains or empties a mind's mailbox                                      | Both need a request signed by the mind, for the host's configured origin (`app.ts` `signedBy`; `app.test.ts`: "gives it to the mind alone")                                                  | None                                                                                                                           |
| A stranger brings a bundle, a record or a feed entry as a mind's                   | The request is signed by the mind itself, and a bundle is judged against its own log. Each entry is the mind's own by its proof as well (`host.ts` `append`)                                 | None                                                                                                                           |
| A signed request is sent again, or sent to this host after it was made for another | Nonces are kept in the database while a signature is valid, and the signature covers this host's origin (`@oip/server` `auth.ts`)                                                            | None                                                                                                                           |
| A `Hello` made for one server is replayed here                                     | Its proof covers the origin and a challenge this host issued, good once and for 300 seconds (`verifyHello`; `sockets.test.ts`: "is closed with 4401")                                        | None                                                                                                                           |
| A socket authenticated as one mind acknowledges for another, or reads its mail     | Mail is sent, and an `Ack` taken, only on a socket whose authenticated mind is the mind of the URL (`sockets.test.ts`: "Another mind's socket", "takes only the mind's own acknowledgement") | None                                                                                                                           |
| A client claims another address to escape its limit                                | As for the resolver: `clientAddress`                                                                                                                                                         | An operator who sets `TRUSTED_PROXIES` too high lets a sender choose its address                                               |

### Tampering

| Threat                                                                             | What stops it                                                                                                                                                                                                  | Left                                                                                                                                                                            |
| ---------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A packet that is refused leaves evidence behind, so that a later judgement differs | A packet is judged as it will be once its proofs are recorded, and they are recorded only if it is kept, in one transaction with the mail (`host.test.ts`: "nothing is kept of it")                            | None                                                                                                                                                                            |
| A second entry replaces or stands beside one at a position of a feed               | The host holds one entry at each position and refuses another valid one (10.3; `host.test.ts`: "holds one entry at each position")                                                                             | A mind that publishes its feed at two hosts can still equivocate. Readers detect it (10.3)                                                                                      |
| A thief with a compromised key keeps a mind's feed from going on                   | Once the mind's log says the key is compromised, the entries it signed from that time on no longer verify, and the mind's next entry replaces them (10.4; `host.test.ts`: "goes on from the last valid entry") | Until the mind publishes the revocation here, the thief's entries stand                                                                                                         |
| The host changes what it serves for a mind                                         | Nothing here. Everything served is signed by the mind, and a reader verifies it                                                                                                                                | A host can withhold: serve an old bundle, or fewer entries. A reader that asks a resolver or another home notices a shorter log, not a shorter feed without a checkpoint (10.5) |
| Mail is lost between the answer and the disk                                       | The acceptance, the mail and the first sight are one transaction, on the disk before `202` is answered (`@oip/server` `storage.ts`)                                                                            | None                                                                                                                                                                            |

### Repudiation

| Threat                              | What stops it                                                                                                                                                   | Left                                                                                |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| A host denies that it took a packet | Where it signs for the mind, the `Ack` is the mind's signed word (13.2). Where it does not, it answers `{ "stored": true }`, which is nothing a sender can show | A host that holds no key gives a sender no evidence. The mind may acknowledge later |
| A mind denies an entry of its feed  | The entry is signed, and served                                                                                                                                 | None                                                                                |

### Information disclosure

| Threat                                                        | What stops it                                                                                                                                                                                                                               | Left                                                                                                   |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| A mind's mail is read by another                              | Only a request the mind signed drains it, and only the mind's own socket is sent it. The answer is marked `no-store`                                                                                                                        | The host and its operator can read every packet that is not sealed. Senders that mind that seal (12.6) |
| An error, a log line or a metric says what should not be said | An unexpected failure is answered `500`, or closes a socket with 1011, with no detail. Metrics are labelled by route and outcome, never by mind or address. A failed lookup is logged by resolver and kind of error only (`lookup.test.ts`) | The operator's proxy may log requests                                                                  |
| Whether a mind is served here                                 | Not hidden: its well-known URL answers. That is what a host is for                                                                                                                                                                          | None                                                                                                   |
| Which senders write to a mind                                 | The host asks its resolvers for the logs of senders it has not met                                                                                                                                                                          | A resolver learns who writes to minds at this host, though not to which                                |

### Denial of service

| Threat                                                               | What stops it                                                                                                                                                                                  | Left                                                                                                                                                                                                                                                                            |
| -------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A mind's mailbox is filled by strangers                              | A mailbox is bounded in items and bytes, an inbox keeps only packets that verify, and delivery is limited for each address (`host.test.ts`: "holds a bounded number")                          | A mailbox takes anything well formed that is addressed to the mind. A stranger with many addresses can fill one, and the mind is unreachable here until it drains it. A limit for each sender needs the sender verified, which a mailbox does not do                            |
| Packets from unknown senders make the host ask resolvers without end | A mind is asked after once a minute at most, eight at once, only at the configured resolvers and only at the path of 17.1 (`lookup.test.ts`)                                                   | Every packet with a new, unknown sender costs one request to each resolver, at the rate the delivery limit allows                                                                                                                                                               |
| A resolver answers slowly, or with a large body                      | `GuardedFetcher`: ten seconds, two megabytes, and nothing but HTTPS to public addresses                                                                                                        | None                                                                                                                                                                                                                                                                            |
| Verifying signatures takes the processor                             | A packet has one sender's proof to verify. A signature that verified is remembered (`@oip/core`), so a bundle or a learned log that comes again costs its reading and its hashing              | As for the resolver: a log seen for the first time is verified in one piece. A learned log of a thousand events takes about a quarter of a second with OpenSSL doing the arithmetic, and the service answers nothing else meanwhile ([ADR-0016](../adr/0016-native-ed25519.md)) |
| Many sockets, or sockets that say nothing                            | A bounded number, a limit on how many an address opens, ten seconds to say `Hello`, a ping that cuts what does not answer, and a bound on the size of a message (`upgrade.ts`; `main.test.ts`) | Authenticated sockets may stay open and idle up to the bound                                                                                                                                                                                                                    |
| A socket that reads slowly makes the host hold its mail in memory    | Mail is sent a batch at a time, and no more while a megabyte waits to be sent (`sockets.test.ts`: "is sent no more than it takes")                                                             | None                                                                                                                                                                                                                                                                            |
| Messages pile up behind a lookup                                     | Sixty-four may wait on one connection, in order. One more closes it                                                                                                                            | None                                                                                                                                                                                                                                                                            |
| A mind the operator admitted stores without end                      | Its records are bounded in bytes and its feed in entries                                                                                                                                       | A record cannot be removed, so a mind that fills its quota stays full                                                                                                                                                                                                           |
| A large or deep body                                                 | As for the resolver                                                                                                                                                                            | None                                                                                                                                                                                                                                                                            |

### Elevation of privilege

| Threat                                                       | What stops it                                                                                                                                                       | Left                                                                                                                              |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| A packet makes the host fetch a URL of the sender's choosing | The host fetches only `{resolver}/oip/v1/resolve/<mindId>`, from origins the operator set, with a content ID that was checked. Nothing in a record is used as a URL | None                                                                                                                              |
| An open host is made to serve minds without end              | `MAX_MINDS`                                                                                                                                                         | A mind taken on is never dropped. The operator removes it from the database                                                       |
| A request reaches SQL                                        | Every statement is prepared with parameters                                                                                                                         | None                                                                                                                              |
| The WebSocket library is turned against the host             | `ws` 8.23.0, with `maxPayload` set, compression off, and no dependency (ADR-0012)                                                                                   | A fault in the library that is not yet known                                                                                      |
| A custodial host's key signs what it should not              | The host signs one thing with it: the `Ack` of a packet it has verified and kept                                                                                    | The key is in the process. A program that gives `Host` a signer is responsible for where the key lives. Keeping keys is M6's work |

## Left open

1. **A mailbox can be filled.** See above. The reference host bounds the harm to one mind's reachability at this endpoint.
2. **Nothing a mind brought can be removed**: no record, no feed entry, no mind.
3. **A host that holds no key gives a sender no evidence of delivery.**
4. **A host can withhold.** A feed without checkpoints gives a reader no way to tell.
5. **Cost of verification**, as for the resolver.
6. **Sealed records to a mind are not opened**, so an inbox does not judge the packet inside, and answers `{ "stored": true }` even where it signs for the mind. A custodial host that also held the mind's agreement key could do both. Not built.

# M2 review: Identity

**Reviewed:** 17 November 2026 · **Diff:** `53dee13..daf7882` on `m2-identity`, then the fixes, and a review of each round of fixes until one found nothing that changes an answer · **Specification revision:** 2026-11-17, with [OEP-0001](../../oeps/oep-0001-core-clarifications.md) and [OEP-0002](../../oeps/oep-0002-identity-clarifications.md)

[BUILD.md](../../BUILD.md), Section 7, asks for a fresh review at the end of each milestone, by an agent whose only context is the repository, the specification and the milestone's diff. M2 had two, run in parallel, each with its own area:

- **Review A: conformance and test quality.** Every rule of Layer 1, Sections 2 to 9, and of core Section 9, against the code and against the Python checker; OEP-0002, point by point; whether each test can fail (118 mutants made by hand, and 17 more run against the differential campaign); whether the acceptance criteria of BUILD.md have evidence.
- **Review B: security.** Forged and backdated events and proofs; removed, retired and compromised keys; duplicity; collectives; resource exhaustion from hostile logs; values that are not plain data; what the evidence interface lets a caller get wrong.

The fixes were large and touched rules that protect people, so they were reviewed in turn:

- **Review C: the fixes.** One agent, given the repository, the specification, the two reports and the diff of the fixes (`daf7882..6bd9ba4`). It ran every probe of the first two reviews again, planted 47 faults in the rules the fixes touched, and compared the two implementations on cases made by hand.
